# P10 Document Skills 插件开发报告

## 结论

P10 已把文档生成做成一个默认关闭、可热启停的声明式插件 `Document Skills`。基础聊天、记忆、RAG 和 Planner 不依赖该插件；用户开启后，Agent 才会获得 DOCX、PDF、PPTX、XLSX 生成能力，关闭后相关 Skill 和 MCP Tool 会立即从能力目录及请求白名单中撤销。

这也是后续从 GitHub 手工下载能力包时可复用的标准形态：一个普通插件文件夹、一份 `plugin.yaml`、若干 `SKILL.md`，以及通过 MCP 隔离运行的外部能力。

## 用户使用方式

1. 打开“设置 → 插件”；
2. 开启 `Document Skills`；
3. 回到对话，直接提出“生成一份 Word/PDF/PPT/Excel”的要求；
4. 工具执行完成后，在工具卡片或最终回答中点击文件名下载；
5. 不再需要时关闭插件，Agent 随即失去这些工具。

当前内置四个 Skill：

- `documents`：创建 DOCX，并可在用户审批后追加已有生成文档；
- `pdf`：创建带中文字体和页码的 PDF；
- `presentations`：创建 16:9 PPTX；
- `spreadsheets`：创建支持多工作表、数值、公式和基础格式的 XLSX。

四个 Skill 的 frontmatter `name` 分别是 `documents`、`pdf`、`presentations` 和 `spreadsheets`，与各自文件夹名严格一致；中文用途写在 `description` 中，以兼容通用 Skill 校验器。

## 运行设计

```text
用户请求
  → Skill 目录判断是否需要文档能力
  → 请求级 Tool 白名单
  → 权限与参数校验
  → Document Skills MCP Server
  → 一次性生成 Worker
  → UUID Artifact 目录
  → 下载 API / 工具结果下载按钮
```

- 插件默认关闭，启停不需要重启后端；
- Tool 仍通过现有白名单、风险审批、超时和 ToolRun 审计；
- 普通新建工具为 `medium` 风险，修改已有 DOCX 为 `high` 风险；
- MCP Server 不在 API 进程内导入文档库；每次生成由一次性 Worker 完成，避免第三方库卡住长期 MCP 会话；
- 每个文件存入不可预测的 UUID 目录，用户文件名只用于下载显示；
- 下载接口按 Artifact ID 解析元数据并验证路径，拒绝路径穿越和符号链接；
- 单个成品最大 50 MiB，并限制文本、幻灯片、工作表、行列数量；
- 工具返回结构化 `ARTIFACT_JSON`，前端即使未从最终模型回答中识别 Markdown，也会显示稳定下载入口。

## 主要文件

- `plugins/document-skills/plugin.yaml`：插件和 MCP 声明；
- `plugins/document-skills/skills/*/SKILL.md`：四类文档能力说明；
- `mcp_servers/document_skills/server.py`：MCP 工具接口；
- `mcp_servers/document_skills/worker.py`：隔离的一次性生成进程；
- `mcp_servers/document_skills/generation.py`：受限文档生成实现；
- `core/files/artifacts.py`：Artifact 存储、元数据和安全定位；
- `apps/api/artifacts.py`：文件列表与下载 API；
- `apps/web/components/ChatView.tsx`：工具结果下载按钮。

## API

```text
GET /api/artifacts
GET /api/artifacts/{artifact_id}
```

生成能力本身不额外开放普通 HTTP 写入接口，只能由已启用 Skill 允许的 MCP Tool 在 Agent 执行链中调用。

## 验收范围

- DOCX 可由 `python-docx` 重新打开，并验证标题、标题层级和正文；
- PDF 可由 `pypdf` 重新打开并验证页数；
- PPTX 可由 `python-pptx` 重新打开并验证幻灯片数量；
- XLSX 可由 `openpyxl` 重新打开并验证文本、数值和公式；
- 真实 stdio MCP 能发现 5 个工具并完成文件生成；
- 下载 API 返回正确文件、文件名与媒体类型；
- 插件启用后注册 4 个 Skill 和 5 个 Tool，关闭后完全撤销；
- 全量后端测试、前端 lint 与生产构建通过。

## 当前边界

P10 是稳定、易测试的第一版文档能力，不是 Office 的完整替代品。当前不支持编辑任意用户本地文件、复杂模板继承、图表自动设计、宏、云端协作和在线插件市场。后续从 GitHub 手工加入其他插件时，应继续保持“来源可见、默认关闭、能力声明、风险审批、进程隔离”的规则。
