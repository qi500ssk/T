# 角色记忆方案评审与本次落地

评审依据：用户提供的《角色 Agent 记忆系统设计方案》与当前项目的实际实现。

## 应保留的方向

Chunk、Event、Memory 分开，事件有原文依据，角色只保存自己的视角；原作记忆与用户互动记忆分开。一次回答只召回少量相关记忆，按 token 预算装配。界面展示可读内容，不需要知识图谱。

## 需要修正的地方

1. **先知情过滤，再按角色判断重要性。** 同一件事对不同人物的意义不同，不能先全局删除“不重要事件”，否则会抹掉某个配角的重要经历。世界事件保留，未通过门控的角色视角进入候选而非自动长期启用。
2. **L1 不保证客观真实。** 原作可能有旁白、误解、不可靠叙述，也可能来自 AI 整理。引文存在仅证明可追溯，不等于它支持所有推断；用户审核与模型置信度不能替代原作核查。
3. **RAG 不能绕过角色边界。** 原作文档包含秘密和未来剧情，不能因用户点选附件就整体进入角色上下文。知识库页的用户核对与角色聊天检索是两条权限不同的路径。
4. **重要事件之外还有稳定知识。** 地点、文化、人物身份与长期习惯不一定是“重大事件”，但角色需要知道。知情世界条目单独标为背景知识，不解释成角色亲历的剧情。
5. **文档顺序不是时间顺序。** 倒叙、插叙与后来获知的消息需要区分。事件支持时间类型、可空顺序和有依据的父事件，不自动按章节推断日期。当前角色创建起点明确为世界书末尾，尚不支持任意时间截点；后者还需要当时的人格、关系及获知时间快照。
6. **默认拒绝是拒绝长期激活，不是删除证据。** 临时线索可以留候选；日后明确事实仍可重新评估。不能仅凭被重复提到就升为事实。
7. **存储与角色边界独立。** 按用户最新要求使用 PostgreSQL + pgvector；角色知情过滤、来源校验与按角色隔离仍由业务层执行，不依赖图数据库。

## 当前实现

- 移除图谱入口、连线与 3D 展示组件及依赖。已有原文和世界事实表仍作为记忆来源保留，不删除用户内容。
- 世界书导入与角色创建迁入知识库。创建时自动生成有依据且知情的角色记忆，界面不要求逐条审批。同名人物按文档内稳定 ID 区分。
- 重要性、情绪、关系变化、保留理由与可信度保存在人物视角。有匹配原文依据的知情视角自动启用；显式低置信内容内部隔离、不召回。旧格式未填写评分时不再要求用户确认全部记忆，重要性用于排序。
- 已有用户确认的角色记忆不按新门控批量改写。新创建角色使用新门控。
- 保存独立角色—世界书绑定、事件 ID、多片段来源及内容哈希；编辑记忆保留这些关联。来源缺失或改变时停止召回。
- 正式角色记忆生成向量，失败时保留关键词召回；上下文使用完整角色记忆而非截断的展示摘要，超预算整条跳过。
- 角色原作检索受限；即使手动选择原作文档，也不会提供全知正文。共享项目记忆不自动灌入故事角色；公共记忆仍仅由用户显式创建。
- 用户聊天中未达长期阈值、且置信度至少 0.5 的线索进入独立候选表。每角色最多 200 条，30 天有效，不参与自动召回。界面不展示候选审批；后续高置信事实可正常入库，舍弃记录在保留期内不自动复活。
- 世界书导出的角色卡区分正式记忆与候选记忆，不混装。

## 尚未实现、不能宣称完成的能力

- 自动将多天聊天合并成可靠的 Major Memory；当前是稳定键去重、版本替换和原对话追溯。
- 任意原作时间截点的人格/知情快照、关系状态重演。
- 主动淡化与按需唤醒的完整状态机。现有停用、过期、候选期限制继续使用。
- 原作事实的自动真实性认证。结构和引用校验可拒绝错误引用，但不能证明模型的语义解释必然正确。

不重新增加图谱。若以后确有需要，可以单独讨论简单的可筛选事件列表/时间列表，先获用户认可再做。
