# P9 MCP 与声明式插件管理开发报告

## 结论

P0-P8 的基础聊天、上下文、记忆、RAG、意图分流、Tool 安全链和 Planner 均保持不变。P9 将 MCP 和插件放在能力层，通过热刷新接入现有 `Skill → Tool 白名单 → 参数校验 → 风险审批 → ToolRun 审计` 流水线，因此新增或关闭能力不会改写聊天主循环。

## MCP Manager

在原有官方 MCP SDK stdio 客户端上新增：

- `stdio` 与 `streamable_http` 两种传输；
- YAML 配置的查询、新建/更新、启停、删除和热刷新；
- 保存前独立连接测试，返回 Server 信息与工具列表；
- 连接状态、错误原因、来源和已注册工具可见；
- 工具名统一为 `mcp_<server>_<tool>`，避免与原生工具冲突；
- 配置启停后立刻注册或撤销 Tool，无需重启后端；
- 环境变量和认证 Header 只返回键名，不向前端回显值；
- 编辑配置时认证字段留空会保留旧值；
- 子进程只继承启动所需的系统环境变量和用户显式配置，不继承模型 API Key；
- 新配置默认关闭、默认高风险；MCP 工具仍需被启用 Skill 明确依赖后才能进入请求级白名单。

主要模块：

- `core/capabilities/mcp.py`：传输、协议适配与 Tool 注册；
- `core/capabilities/mcp_manager.py`：状态、持久化和热连接；
- `apps/api/mcp_servers.py`：管理 API；
- `apps/web/components/McpView.tsx`：设置界面。

## 声明式插件

P9 没有引入可在 API 主进程内执行任意 Python/JavaScript 的插件系统。一个插件是普通文件夹：

```text
my-plugin/
├── plugin.yaml
└── skills/
    └── my-skill/
        └── SKILL.md
```

`plugin.yaml` 可以声明基本信息和 `mcp_servers`。启用插件时，系统注册它的 Skill Provider，并把 MCP 配置临时加入 MCP Manager；关闭插件时两者一起撤销。插件 MCP 名称自动加插件命名空间。

安装规则：

- 浏览器直接选择普通文件夹，不需要 ZIP；
- 根目录必须有且只有一个 `plugin.yaml`；
- 最多 200 个文件、总计 10MB、单文件 4MB；
- 只允许文档、配置和常见图片类型；`.py`、`.js`、`.exe` 等可执行内容直接拒绝；
- 安装使用临时目录校验后原子替换；
- 新插件无论清单原值如何都默认关闭；
- 删除移动到 `data/plugin-trash`，可人工恢复；
- 内置 `starter-pack` 是无需外部依赖的开关测试样例。

该边界支持“从网上下载一个 Skill/MCP 组合文件夹后加入助手”，又不会让第三方代码直接进入稳定的聊天进程。以后可在此基础上增加在线目录、来源签名、权限预览和版本更新。

## 设置界面

设置导航现已包含三个可操作页面：

1. 技能：扫描、搜索、创建、导入、开关和删除；
2. MCP 服务器：本地/HTTP 配置、连接测试、状态、开关和删除；
3. 插件：普通文件夹导入、刷新、能力数量、开关和可恢复删除。

所有动态结果均使用可访问的 live region，按钮有键盘焦点状态，开关有屏幕阅读器标签，布局在移动端与桌面端均可用。

## 当前边界与下一步

P9 支持本地普通文件夹和手工 MCP 配置，但尚未直接从 URL/GitHub 搜索并安装。下一步应先实现只读在线目录与安装预览，展示来源、文件清单、所需工具、MCP 地址和风险等级，经用户确认后下载，并继续保持默认关闭。远程可执行能力优先通过受限 MCP 子进程或认证 HTTP 服务接入。
