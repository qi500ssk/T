# P11 简单编码能力开发报告

## 结论

P11 已把基础编码做成默认关闭的 `Developer Tools` 插件。它不是一个可任意操作电脑的完整编码 Agent，而是一组适合当前个人助手的受限能力：查看项目结构、搜索和读取代码、创建新文件、精确修改已有文件、查看 Git 未提交改动，以及运行预定义检查。

基础聊天、记忆、RAG、文档生成和其他插件不依赖编码能力。关闭插件后，`coding-helper` Skill 与 7 个编码工具都会从新请求的能力白名单中撤销，能力页也显示为未启用。

## 如何使用

1. 在 `.env` 中配置希望 Agent 操作的项目目录：

   ```env
   CODING_WORKSPACE_DIR=E:/Pycharm/JQ/your-project
   ```

   不配置时使用 `./data/coding-workspace`。修改工作区配置后需要重启后端。

2. 打开“设置 → 插件”，开启 `Developer Tools`；
3. 回到对话后，可以提出：

   - “查看项目文件”；
   - “搜索代码：build_context”；
   - “读取代码：src/app.py”；
   - “创建代码文件：hello.py 内容：print('hello')”；
   - “修改代码文件：hello.py 将：hello 改为：你好”；
   - “查看代码改动”；
   - “运行代码检查：python-compile”。

4. 创建、修改或运行检查时确认审批卡片；
5. 不再需要时关闭插件。

Mock 模型主要用于验证固定格式。接入真实支持 Tool Calling 的模型后，可以直接用自然语言描述任务，Agent 会根据 Skill 说明组合查看、修改和检查步骤。

## 提供的工具

| 工具 | 用途 | 风险等级 |
|---|---|---|
| `code_list_files` | 列出受限数量的项目文件 | medium |
| `code_search` | 在文本代码中搜索内容 | medium |
| `code_read` | 按行读取单个代码文件 | medium |
| `code_git_diff` | 只读查看 Git status 和 diff | medium |
| `code_create_file` | 创建新文件，不覆盖已有文件 | high，需审批 |
| `code_edit` | 仅替换唯一匹配的精确文本 | high，需审批 |
| `code_run_check` | 运行预定义项目检查 | high，需审批 |

预定义检查只有：`pytest`、`python-compile`、`npm-test`、`npm-lint`、`npm-build`、`npm-typecheck`。用户输入不会拼接成 Shell 命令。

## 安全设计

- 所有路径都必须位于 `CODING_WORKSPACE_DIR`，拒绝绝对路径、`..` 越界和符号链接；
- 默认忽略 `.git`、`.venv`、`node_modules`、缓存和构建产物；
- 拒绝读取或写入 `.env`、凭据文件、SSH 私钥、证书私钥等敏感文件；
- 新建文件不会覆盖已有内容，修改要求 `old_text` 恰好匹配一次；
- 写入采用临时文件加原子替换，避免半写入状态；
- 检查进程使用固定命令、超时、输出上限和清理后的环境变量；
- 当前没有删除、移动、任意 Shell、依赖安装、联网、Git commit/push/reset 等能力；
- Planner、Skill 或模型不能扩大权限，所有调用仍经过请求白名单、审批、超时与 ToolRun 审计。

## 主要文件

- `plugins/developer-tools/plugin.yaml`：默认关闭的插件清单；
- `plugins/developer-tools/skills/coding-helper/SKILL.md`：编码工作流程和工具声明；
- `core/execution/coding_tools.py`：隔离路径、读写、Git diff 和检查实现；
- `core/execution/tools.py`：工具参数 Schema、风险等级与注册；
- `core/execution/executor.py`：审批摘要与统一执行链；
- `core/capabilities/registry.py`：根据当前 Skill 标记工具启用状态；
- `core/chat/gateway.py`：Mock 模型的基础编码测试意图；
- `tests/test_coding_tools.py`：路径、敏感文件、写入、检查、插件开关和 Mock 意图测试。

## 当前边界与后续方向

这一版用于证明“安装并开启一个能力后，普通聊天助手可以安全获得编码能力”。它适合小范围查看、单点修改和已有项目检查，不适合大型跨文件重构、交互式终端、依赖安装和自动提交。

后续如果确实需要更强编码能力，应继续作为可选插件演进：先增加工作区选择与变更预览，再考虑补丁式多文件编辑、受控命令配置和 Git 提交。不能把任意 Shell 直接塞进基础聊天能力。

## 验收结果

- 编码专项覆盖路径越界、敏感文件、依赖目录、读取/搜索、创建、唯一匹配编辑、Git diff 和预定义检查；
- 覆盖插件关闭/开启时编码工具在 Capability Registry 中的状态；
- 覆盖 Mock 模型的查看、搜索、读取、创建和检查意图；
- `coding-helper` 已通过通用 Agent Skill 格式校验；
- 全量后端测试：`114 passed, 1 skipped`，跳过项为当前 Windows 环境无权创建符号链接；
- 前端 lint、TypeScript 与生产构建通过。
