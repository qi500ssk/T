# P4 阶段开发报告：连接外部世界

## 交付结果

P4 已完成最小 stdio MCP 适配闭环。应用启动时通过官方 MCP Python SDK 连接配置中的 Server，发现工具并转换为现有 `Tool`；MCP 工具继续使用 P3 的 Skill 白名单、固定风险、审批、SSE 和 `tool_runs`，没有建立第二套执行系统。

## 已实现能力

- `core/capabilities/mcp.py`：YAML 配置解析、stdio Client、工具发现、调用和关闭；
- 模型工具名使用 `mcp_{server}_{tool}`，满足 OpenAI-compatible 命名约束；
- MCP 文本、结构化内容和错误结果转换为现有字符串工具结果；
- 工具注册冲突时不覆盖，关闭时只注销当前 Client 注册的名称；
- 单个 MCP Server 连接失败时跳过，不影响应用和其他 Server；
- `scripts/mcp_demo_server.py` 提供 `echo` 和 `random_number`；
- `mcp_demo_echo` 为 low，自动执行；
- `mcp_demo_random_number` 为 high，复用现有用户审批；
- MCP 工具由 `skills/mcp-demo/SKILL.md` 声明后进入请求白名单。

## 生命周期

```text
启动：Provider -> MCP connect/register -> Skill load -> 接受请求
关闭：拒绝审批 -> MCP unregister/close -> Provider close
```

`MCP_ENABLED=false` 时不读取配置或启动子进程，应用行为与 P3 一致。测试环境默认使用该设置，保持既有测试隔离。

## 验证结果

```text
pytest: 64 passed, 1 skipped
MCP:    initialize / tools/list / tools/call passed
API:    lifespan register / skill load / unregister passed
```

跳过项仍是当前 Windows 环境无权限创建符号链接，与 MCP 无关。

专项验证覆盖：

1. Demo Server 真实 stdio 握手、工具发现和调用；
2. MCP 返回文本、结构化内容和 `isError` 适配；
3. 坏 Server 不阻止正常 Server 连接；
4. Skill 白名单、Tool Router、high 审批和 `tool_runs` 全链路；
5. shutdown 后 MCP 工具从 `TOOLS` 注销并回收子进程。

## 当前限制

P4 只支持可信本地配置的 stdio Server，不支持第三方凭据、HTTP 传输、热加载、自动重连、资源型结果展示和按意图动态 Skill 选择。这些能力等出现真实需求后再增加。
