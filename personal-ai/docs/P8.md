# P8 渐进式能力运行时开发报告

## 目标

在 P7 普通 Skill 文件夹管理基础上，吸收 DeepSeek Harness 对当前产品真正有价值的部分，同时避免把整个聊天应用改造成复杂插件框架：

1. Skill 正文按需加载，不再全部占用每次模型请求的上下文；
2. Skill 来源统一通过 Provider Registry 发现，为本地、内置和未来在线目录预留稳定接口；
3. 每次 Agent Run 持久化能力快照和版本，能够解释“当时可以使用什么”；
4. Tool Executor 增加前置安全策略和后置结果处理扩展点。

参考设计：[DeepSeek Harness Architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)、[Skills](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/skills.md) 和 [Tool Execution Pipeline](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-execution-pipeline.md)。

## Skill 渐进加载

此前 `render_skill_instructions()` 会把所有启用 Skill 的完整正文加入 System Prompt。P8 只加入 Skill ID、显示名称和用途说明。

当模型判断当前问题需要某项 Skill 时，调用低风险工具：

```json
{"name": "skill_load", "arguments": {"name": "writing-helper"}}
```

`skill_load` 只能读取本次 Run 开始时已启用的 Skill 快照。其他 Skill、已关闭 Skill 和运行中途新安装的 Skill 均不可读取。完整正文以受限 `<skill_content>` 返回，并明确不能覆盖系统规则、安全策略、工具权限或用户要求。

Skill 仍负责“如何做”，Tool/MCP/Plugin 负责“能够做什么”。启用 Skill 所需的 Tool 继续进入请求级白名单，关闭 Skill 后新 Run 不再获得对应工具权限。

## Skill Provider Registry

新增 `core/capabilities/skill_registry.py`：

- `SkillProvider.list()` 提供统一候选目录；
- `SkillRegistry.register()` 注册并返回可撤销 disposer；
- Provider 按优先级解决相同 Skill ID 冲突；
- Provider 暂时失败时保留最后一次可用目录，并将快照标记为 `complete=false`；
- 快照生成稳定 SHA-256 版本；
- 当前 `DirectorySkillProvider` 继续扫描普通 `skills/<id>/SKILL.md` 文件夹。

新增 `GET /api/skills/catalog`，返回目录版本、完整性和 Skill 数量。后续在线目录只需实现新的 Provider，不需要修改 Agent 主循环。

## Run 能力快照

`agent_runs` 新增：

```text
capability_version  SHA-256 版本
capability_snapshot JSON 快照
```

快照包含本次 Run 的 Skill ID、显示名称、所需工具、正文摘要哈希以及最终工具白名单，不保存完整 Skill 正文。`run.started` SSE 同步返回能力版本和启用 Skill ID。

SQLite P8 迁移可重复执行，旧 Run 允许快照为空，新 Run 写入当前快照。

## Tool 安全流水线

新增 `core/execution/tool_pipeline.py`：

- `register_pre_tool_hook()`：参数校验后、审批和执行前运行；返回原因即可拒绝调用；策略异常 fail-closed；
- `register_post_tool_hook()`：执行后按顺序规范化或观察 `ToolExecution`；异常被隔离，不覆盖已经产生的权威结果；
- `ToolInvocation` 使用只读参数映射，携带 Run、会话、步骤、工具和风险身份。

现有白名单、参数校验、风险审批、超时、ToolRun 持久化和后台拒绝规则保持不变。未来 Plugin、MCP 统一策略、审计与脱敏可以注册 Hook，不再直接修改 Executor。

## 明确未照搬的部分

P8 不引入 Cordis、npm Bundle、进程内任意第三方代码和完整事件溯源。当前产品面向普通用户，基础聊天稳定性和安装安全比“Everything is a Plugin”更重要。

第三方可执行能力仍应优先使用隔离 MCP/子进程；纯 Skill 文件夹保持不可自动执行脚本。

## 验收

```text
后端：99 passed, 1 skipped
前端：npm run lint 通过
前端：npm run build 通过
```

覆盖 Provider 优先级、失败回退、Skill 正文不进入初始提示词、按需加载、未启用拒绝、工具策略 fail-closed、能力快照持久化和目录状态 API。
