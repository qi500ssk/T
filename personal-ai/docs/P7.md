# P7 本地技能管理开发报告

## 目标

在不破坏基础聊天的前提下，实现“目录即安装”的轻量 Skill Manager：把合法 Skill 文件夹放入 `personal-ai/skills/`，刷新后即可在设置页看到并选择启用。

## 开发前基础聊天审计

当前聊天底座足以支撑首期 Skill 扩展：

- FastAPI SSE 流式事件和消息持久化完整；
- Context Engine 对 System、Memory、RAG、Summary、近期消息和当前问题实施总 token 硬预算；
- 会话摘要增量更新，长期记忆支持提取、召回、纠正、禁用和敏感信息过滤；
- RAG 只展示正文实际使用的引用，未知引用不会生成来源卡片；
- direct 模式由模型根据 Skill 描述和工具 Schema 完成意图/工具选择；
- 同会话只允许一个 running Run，工具风险审批、超时、取消和失败状态均有收口；
- Skill、MCP 或后处理故障不会使已经完成的基础回答失败。

开发前全量基线为 `87 passed, 1 skipped`。首期只有少量短 Skill，不增加独立意图分类器，避免重复模型调用和错误路由；后续 Skill 数量显著增长时再做按描述召回和渐进加载。

## 后端实现

### Skill 扫描

`core/capabilities/skills.py` 现在提供两层结果：

- `scan_skills()` 返回全部扫描项，包括关闭、缺少依赖和格式错误项；
- `load_skills()` 只返回当前真正可运行的 Skill，保持既有 Agent 调用兼容。

扫描使用 `yaml.safe_load`，校验 name、description、required_tools、enabled 和非空指令。未知 Tool 不执行，设置页显示“缺少依赖”；错误 Skill 不影响其他 Skill。

### 状态持久化与运行时刷新

新增 `assistant_skills` 表，以 `(assistant_id, skill_id)` 保存开关。当前使用 `default` Assistant，同时为后续多角色隔离预留键。

新增 API：

```text
GET   /api/skills
POST  /api/skills/refresh
POST  /api/skills/import-folder
POST  /api/skills
PATCH /api/skills/{skill_id}
DELETE /api/skills/{skill_id}
```

刷新和开关会原地更新运行时 Skill 列表并重建 Capability Registry。进行中的 Run 使用已有快照，新 Run 使用最新列表；Activity Worker 持有同一个列表对象，因此也能看到刷新结果。

## 前端实现

删除不符合当前产品目标的只读 `CapabilityView`，保留后端 Registry 供 Planner 和调试使用。

界面调整为两层：

- 工作区：对话、记忆、知识库、活动和最近会话；
- 设置工作区：独立左侧导航和技能管理页，MCP/插件明确标记为后续。

技能页提供搜索、重新扫描、普通文件夹导入、新建表单、来源分组、状态、缺失依赖提示、详情、可恢复删除和可访问的开关。动态结果通过 `aria-live` 播报，弹窗使用原生 modal dialog 管理焦点和 Escape，键盘焦点可见，并尊重 reduced-motion。

### 普通文件夹安装

用户可以直接把 `技能目录/SKILL.md` 复制到 `skills/` 后刷新，也可以在界面选择整个普通文件夹导入，不要求压缩为 ZIP。导入器执行以下约束：

- 根目录必须恰好存在一个 UTF-8 `SKILL.md`；
- 最多 100 个文件、单文件 2MB、总计 5MB；
- 拒绝绝对路径、`..` 路径穿越、重复路径和脚本/可执行文件；
- 仅保留说明文档、配置和静态资料，Skill 不会因下载而自动获得代码执行权限；
- 安装使用同卷临时目录和原子重命名，冲突时不覆盖现有 Skill；
- 外部 Skill 统一标记为 `local` 且默认关闭；
- 删除只适用于本地 Skill，并移入 `data/skill-trash/`，内置与开发测试 Skill 不可删除。

新建表单会生成标准 Skill 文件夹和 `SKILL.md`，并验证所声明的 Tool 已在本项目注册。

## 当前边界与下一步

当前不实现 ZIP、Git/URL 自动拉取、在线市场、MCP 管理页和完整 Plugin Runtime。用户从网上获得普通 Skill 文件夹后已经可以导入；下一阶段可增加“在线发现 → 下载预览 → 用户确认安装”，但仍应保持安装与启用分离。复杂图片、音乐和编码能力按真实需求后置。
