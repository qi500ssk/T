# P6 阶段开发报告：高级 Agent

## 交付结论

P6 已按“受限 Planner 最小闭环”完成。现有 Chat 和 Activity 默认保持 `direct`；用户明确选择 `planned` 后，系统会在同一个 AgentRun 内生成严格结构化计划、顺序执行步骤、在受阻时最多重规划一次、无工具汇总最终结果，并持久化完整的 Plan / PlanStep 状态。

这不是无限自治系统。Planner 不能调用工具、修改权限、创建 Activity、安装插件或生成子 Agent；所有动作继续经过共享 Executor、Skill 工具白名单、风险等级、审批与 ToolRun 记录。

## 核心实现

### 1. 数据完整性与迁移

- `AgentRun`、`Activity` 新增 `execution_mode`，历史数据默认回填 `direct`。
- 新增 `Plan`、`PlanStep`，保存目标、版本、顺序步骤、状态、摘要和错误，不保存隐藏推理。
- SQLite 使用部分唯一索引保证同一 Conversation 只能有一个 `running` AgentRun。
- 启动迁移会安全收尾旧库中可能遗留的重复 running Run，并可重复执行。
- 删除 Conversation 前拒绝 running Run 或 Activity 引用；安全删除时显式清理 PlanStep、Plan、ToolRun、AgentRun 和 Message。

### 2. Planner 与共享 Executor

- `core/automation/planner.py` 负责 create / replan JSON、严格字段和长度校验、工具提示白名单、重复步骤拒绝和状态操作。
- `core/execution/executor.py` 是 direct / planned 唯一的模型—工具循环，继续复用现有 Tool、MCP、审批和 ToolRun 链路。
- planned Run 受总超时、最大步骤、每步模型轮次、全 Run 工具次数、观察摘要预算和 Replan 次数共同限制。
- Replan 只替换 blocked / pending 步骤，已完成步骤和摘要保留；最终 Synthesis 不提供工具。
- Planner 输出无效时不猜测执行：Plan 与 AgentRun 标记 failed，并向会话保存安全的说明消息。

### 3. Activity、API 与界面

- Activity 创建时可选择 direct / planned；后台仍使用 `approval_mode="deny"`，high 工具立即 rejected。
- 服务重启会取消遗留的 running AgentRun / Plan / PlanStep，再按 P5 语义重新排队整个 Activity，不恢复半个计划。
- 新增 Plan 详情、Conversation Plan 历史、Activity Plan 历史和 Capability API。
- Chat 显示执行模式切换和实时步骤；Activity 显示执行模式；Capability 页面展示启动时真实加载的 Tool、Skill、MCP 快照。
- Plan SSE 只包含可展示状态与截断摘要，不包含完整 Prompt、隐藏推理、凭据或完整工具结果。
- RAG 增加轻量查询门控；计算、问候、当前时间/天气和纯写入任务不再检索个人资料库。
- 检索候选只有在回答正文实际出现对应 `[cN]` 时才会持久化和展示；前端也会过滤历史消息中的未引用来源。

## 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plans/{plan_id}` | Plan 与所有版本步骤 |
| GET | `/api/conversations/{conversation_id}/plans` | 会话最近 20 个 Plan |
| GET | `/api/activities/{activity_id}/plans` | Activity 的 Plan 历史 |
| GET | `/api/capabilities` | 只读 Capability Registry |

`POST /api/chat` 与 `POST /api/activities` 新增可选字段：

```json
{"execution_mode": "direct"}
```

允许值为 `direct | planned`，缺省为 `direct`。

## 新增事件

```text
plan.created

plan.step.blocked
plan.replanned

```

既有 `run.* / message.* / tool.* / approval.* / rag.retrieved` 协议保持兼容。

PLANNER_MAX_STEPS=6

未实际生效的 `AGENT_MAX_RETRIES` 已删除，避免产生流式或写操作会自动重试的错误预期。

## 验证范围

- Planner schema、未知工具、重复步骤与无效 JSON 安全失败
- direct 行为回归、单 planned Run / Message、共享工具预算
- blocked Replan、完成步骤保留、后台 high 拒绝且无审批 waiter
- planned Activity、重启恢复、Plan / Capability API
- 同会话 running Run 唯一约束、会话删除清理和 P6 迁移幂等
- RAG 与 Planner 固定评测
- 前端 Lint 与生产构建

## 保留边界

P6 仍是单用户、单 API 进程、单 Activity Worker 的本地实现。没有 DAG、并行步骤、自动 planning gate、无限 Replan、自治目标、Activity 自修改、插件安装、多 Agent 或分布式锁。只有实际使用数据证明顺序受限 Planner 不足时，才进入下一轮架构扩展。
